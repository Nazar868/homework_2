## Завдання 1. Аналіз відкритих портів

Для перегляду відкритих мережевих портів використано команду:

```bash
ss -tuln
```


**Порт №2**

- Порт: [номер порту]
- Стан: [LISTEN або UNCONN]

**Порт №3**
- Протокол: [TCP або UDP]
- Порт: [номер порту]
- Стан: [LISTEN або UNCONN]

### Висновок

За допомогою команди `ss -tuln` було перевірено відкриті мережеві порти комп'ютера. Визначено протоколи TCP та UDP, номери портів і їхні стани. TCP використовує стан LISTEN для портів, які очікують на вхідні з'єднання, а UDP не встановлює з'єднання, тому для нього зазвичай відображається стан UNCONN.

## Завдання 3. Перевірка TCP-з'єднання

Для перевірки TCP-з'єднання з сервером Google використано команду:

```bash
nc -vz google.com 80
```

### Результат виконання команди

```text
[Вставити результат виконання команди]
```

### Аналіз результату

- Тип з'єднання: TCP.
- Домен: google.com.
- Порт: 80.
- Результат: [з'єднання встановлено / з'єднання не встановлено].

### Висновок

За допомогою команди `nc` було перевірено можливість встановлення TCP-з'єднання з сервером Google через порт 80. TCP передбачає встановлення з'єднання між клієнтом і сервером та підтвердження отримання даних. Якщо з'єднання успішне, це означає, що сервер доступний через вказаний порт.

## Завдання 4. Порівняння TCP та UDP

Для перевірки UDP-з'єднання виконано команду:

```bash
nc -u -vz 8.8.8.8 53
```

### Результат UDP

```text
[Вставити результат виконання UDP-команди]
```

Для перевірки TCP-з'єднання виконано команду:

```bash
nc -vz 8.8.8.8 53
```

### Результат TCP

```text
[Вставити результат виконання TCP-команди]
```

### Порівняння результатів

**TCP:**
- Порт: 53.
- Протокол: TCP.
- Особливість: встановлює з'єднання перед передаванням даних.
- Результат: [описати результат перевірки].

**UDP:**
- Порт: 53.
- Протокол: UDP.
- Особливість: не потребує встановлення з'єднання.
- Результат: [описати результат перевірки].

### Висновок

TCP та UDP є транспортними протоколами, але мають різні принципи роботи. TCP встановлює з'єднання та забезпечує контроль доставки даних. UDP працює без встановлення з'єднання, тому не гарантує доставку пакетів.

Порт 53 використовується DNS-службою. DNS може працювати як через UDP, так і через TCP. Результат перевірки UDP за допомогою netcat не є повноцінним підтвердженням доступності DNS-сервера, оскільки UDP не має механізму встановлення з'єднання.

## Завдання 5. DNS резолвінг

Для отримання IP-адреси домену використано команду:

```bash
nslookup github.com
```

### Результат виконання команди

```text
[Вставити результат команди nslookup github.com]
```

### Аналіз результату

- Домен: github.com.
- IP-адреса: [отримана IP-адреса].
- DNS-сервер: [адреса DNS-сервера, який відповів].

### Висновок

За допомогою команди `nslookup` було виконано DNS-запит для домену github.com. DNS-сервер перетворив доменне ім'я на відповідну IP-адресу. Це дозволяє користувачам звертатися до вебсайтів за зрозумілими доменними іменами замість запам'ятовування числових IP-адрес.
